# 宽基资金观察

ETF 页面新增“宽基资金观察”，原功能保留在“行情与方向”。`/etfs?view=funds&date=YYYY-MM-DD` 可分享定位；触发提醒使用 `fund_batch` 锁定保存时的快照。

观察篮子版本 `broad-v1-10`：沪深300（510300、510310、510330、159919）、上证50（510050）、中证500（510500、159922）、中证1000（512100、159845、560010）。固定篮子不代表全部宽基，也不表示这些基金均由特定机构持有，不作为历史选股回测样本。

## 数据和计算

- 只使用 Tushare：`fund_basic` 核对基金身份和上市日期；`fund_daily` 提供成交和价格；`fund_share` 提供份额；`fund_nav` 提供单位净值及公告日；`fund_adj` 核对复权和折算风险。当前账号无 `etf_share_size` 权限，首版不依赖它。
- 后台取最近 45 个官方交易日，支持近20日记录和每一天的前20日成交额中位数基准。按每只基金的日期区间取数，不依赖可能截断的全市场日线；份额批量查询固定10只。字段、范围、代码、日期和分页上限校验失败不发布本轮快照，旧数据继续保留。
- 金额内部用 Decimal 字符串。`fund_daily.amount` 千元乘1000转换一次；`fund_share.fd_share` 万份乘10000转换一次。
- 金额估算为相邻真实交易日份额差乘本日单位净值。单位净值不能用成交价替代；任一端份额或复权因子缺失则未知，因子变化的分红/折算期间暂停估算。该估算包含实物申赎、套利等可能，不能当作实测现金净流入或特定机构交易。
- 行情日期、份额估算日期分别固定为各渠道最近有样本的交易日，同一列不拼接不同基金的不同日期。有效样本不足时篮子总额、方向合计留空；缺失不补零，不跨缺失日拼接“连续”。净值公告日、实际采集时间单独列出，历史查询截断到所选日期，不把后补资料当作当时已知。
- 成交异动：成交额至少1亿元且达到前20个真实交易日中位数2倍。至少3只基金、跨2个指数方向同时满足才生成篮子提醒。方向连续净增加提醒要求方向内全部样本最近3个真实交易日估算为正，且当日估算至少5000万元。资料不足不解除已有触发。提醒复用短线模块的已读、忽略、升级和历史快照。

## 披露登记

“原文明示已买入”“未来计划”“报告期末持仓”分开登记。用户必须打开原文核对并明确勾选确认，填写主体、公告日、标题、原文链接、事实摘要；持仓披露另填报告期末。原文未明确具体基金则基金范围留空，登记为市场整体披露。

来源链接限汇金、证金、沪深交易所及证监会官方域名。系统只存人工登记，不抓取或验证网站，不新增其他自动数据源，也不调用 AI。不能将公告归属与基金整体估算绑定为同一笔买卖。登记可撤回、恢复，修订追加，原始记录和核对时间继续保留。当前登记状态与公告日期分开，不作历史点时证明。

## 运行

新增 `BroadFundBatch` 与 `BroadFundEvidence`，运行 `python -m scripts.migrate_add_broad_funds`，重复迁移安全。采集使用 `python scripts/sync_broad_funds.py`；`--refresh` 明确核对订正，`--history` 初始化时不补发新行情提醒。所需数据齐备后复用缓存，后台与手动提交共享 `broad-funds` 锁。

份额、净值和行情可能分批发布。次日上午10点前为等候窗口，超过则显示待补齐，实际连接和权限故障独立记录为失败。`install_broad_funds_monitor.py` 管理独立 cron 区块，先备份并保留其他任务：每天09:05、10:05及工作日16:55、20:55、22:55；周末早间也可补齐周五资料。

读取接口 `/api/etfs/funds`、`/history/{code}`、`/evidence`、`/evidence/{id}/history` 均只读本地数据且要求登录；写入为 `/sync`、`/evidence` 与 `/evidence/{id}/withdraw`。页面刷新不调用行情或模型。市场数据无论何种组合，都不自动标记“国家队进场”或输出身份概率。
