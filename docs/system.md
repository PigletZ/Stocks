# 系统管理

## 功能入口

- 系统管理页：`/system`，包含运行概况、数据与任务、配置与维护。

## 接口

- `GET /api/system/status`：只读取本地状态，不访问 Tushare。
- `POST /api/system/diagnostics`：手动采样交易日历、股票、指数、ETF、股票/基金复权因子及三张财报，共 9 个接口。因子校验证券、日期和正有限值。并发最多 4 个，30 秒内复用结果，10 分钟后标记为待复查。检查不等于业务数据已同步。
- `GET /api/system/maintenance`：轻量读取维护进度，不查全量行情，不调用数据源。
- `POST /api/system/maintenance/{action}`：仅允许 `daily`（近期 3 个交易日补漏）、`factors`（35 个交易日因子回填）、`backup`（一致性校验备份）。返回 202 表示提交结果，不代表任务完成。任务在独立子进程中运行，共用原脚本的跨进程锁及真实执行记录；重复提交和 60 秒内重试复用状态。提交失败、排队进程退出、实际任务中断及待发布均分别显示。未发起的维护为“按需执行”，不当作失败。
- `PUT /api/system/preferences`：保存白名单内的数值参数，拒绝凭据和未声明字段，参数有范围及整数校验，后续请求生效。
- 所有接口沿用全站登录验证。返回结果不包含 Tushare Token、登录密码或签名密钥；日志摘要和错误信息脱敏。

## 监控内容

### 数据缓存（9 张表）
市场统计 / 指数日线 / 板块日线 / 个股行情快照 / 股票复权因子 / 涨停明细 / 龙虎榜 / 财务亮点榜 / K线（主板）
- 官方日历必须覆盖完整所需区间，读取与 ETF 共用的日历文件。未取得日历时标记时效待确认，不能用工作日推算。
- 默认北京时间 21:00 后按当天交易日核验，此前按上一交易日核验；遇休市顺延到最近交易日。这是软件的运营检查规则，可在页面调整，并非上游发布时间承诺。
- 显示最新记录日期、核验日期、核验日期的记录数。指数检查固定 5 个代码，个股及主板 K 线参考本地股票池与有效价格，板块参考前一有数据日及行业/概念类别，涨跌停明细参考同日市场统计。覆盖率是核验提示，停牌和股票池变化可能影响结果。
- 不在刷新时统计全部历史 K 线行数。空表、未知状态、部分覆盖、缺失任务均纳入异常汇总。
- 财务亮点榜日期只代表榜单计算日期；三表是否验证成功须结合财务任务记录。
- 区间复权覆盖分别检查股票 5/10/20 日及 ETF 2/5/10/20 日窗口。分母仅为起止日都有有效报价的证券，分子还要求相同日期的有效因子；不默认因子为 1，不读未来资料。ETF 只纳入缓存基础资料中的存续 ETF。报价滞后、缺官方日历、缺报价对和缺因子分别提示，缓存文件存在不代表对应日期有效。
- 系统页“数据与任务”和“配置与维护”提供补漏/回填/备份操作及进度，运行中轻量轮询，结束后刷新完整数据状态；不会因打开页面自动执行维护。

### 同步任务与计划
- 从当前服务账号的 `crontab -l` 识别已知脚本的实际计划及 cron 时区，显示最近/下次计划时间。读取失败时明确显示未知，不把页面常量当作实际计划。
- K 线脚本也包含快照同步，因此快照可能对应多个计划。
- 日概览任务补齐最近三个真实交易日的统计、指数、板块和涨跌停明细，不再只检查是否已有一行；休市期间运行也可补漏之前的交易日。统计与指数使用完整数据校验后统一提交。
- 晚间补齐安装命令：在 backend 下执行 `venv/bin/python scripts/install_daily_catchup.py`。校验现有时区后，在原 cron 之外管理工作日 18:30、20:30 的补齐区块，保留其他任务，重复安装不新增重复项。修改前的配置备份保存在受保护的 `.cache/system/cron-before-catchup.json`。
- 未发布或暂不能确认完整的数据计为“待发布/核验”，与实际请求/写入失败分开；不会因为单次返回空表就标记同步完成。旧版执行记录没有该计数时按 0 展示。
- 补漏降噪：15 点前只把上一自然日作为查询截止，再用真实交易日历选出最近三个交易日。收盘后继续尝试当天；在配置的就绪时点前，有效空响应计入“正常等候发布”，与失败及逾期待核验分开。到达预计核验时间仍未补齐时，读取状态会升级为需关注，不永久保持等候。网络、权限及错误日期按真实失败记录，不作为正常等候。
- 已完成的数据集按本地完整度跳过；已校验的 ETF 因子在 24 小时内复用，缓存命中不计新写入。晚间管理区块增加 21:30、22:30、23:30，与可配置的 16–23 点核验窗口配合；只重试未完成项，保留其他 cron。短线收盘扫描随后在各小时 35 分执行。
- 板块同步严格区分基础资料不齐、请求失败、错误日期和有效空行情；只有有效空行情作为待发布处理。行业/概念基础资料完整获取后才发布内存映射，中途失败不会缓存半份映射；读取页面仍可保留旧缓存。
- `job_monitor.tracked_job` 为现有日概览、快照、K 线、财务同步记录 UTC 开始/结束时间、成功/失败/跳过单位数、写入或覆盖行数，以及最近 5 次历史摘要。Linux 使用 `flock` 防止同类任务重复执行。
- 区分运行中、完成、部分失败、失败、已确认跳过、待核验和进程中断。计划超过 30 分钟没有对应新执行记录时，旧成功记录不再显示为当前成功。
- 旧日志只供排查：日志更新时间不是开始时间，旧错误不覆盖新执行结果。首次部署后无结构化记录的任务保持待核验，直到任务实际执行。
- 财务定时校验使用严格模式，上游失败不能当作“没有新财报”，故障时不继续刷新亮点榜；页面读取原有财务缓存的兼容行为保留。
- 三张财报先完整拉取和校验，再在同一事务中写入；缺少同报告期的任意一张表、缺少公告日期或发生写入失败时，不会只提交利润表并跳过后续修复。页面回退到缓存时显示提示。

### 配置、缓存与备份

- 常用参数：请求超时 3–30 秒、故障退避 10–300 秒、收盘核验起点 16–23 点、日历缓存 1 小时–7 天、ETF 基础资料 5 分钟–1 天、ETF 日线 1–60 分钟、ETF 日线快照上限 20–365 个。
- 非敏感设置、诊断与任务状态默认存于 `backend/.cache/system/`，可通过 `SYSTEM_STATE_DIR` 调整。采用临时文件加原子替换，设置损坏时使用默认值并提示异常。
- 全站 Pro 客户端统一使用显式检查 HTTP 状态与返回结构的 Tushare 适配器，分页失败不将部分页面作为全量结果返回。
- 备份命令：在 backend 下运行 `venv/bin/python scripts/backup_database.py`。通过 SQLite backup API 生成一致性副本，执行 `quick_check` 后才发布备份和成功记录，默认存于 `backend/backups/`，可通过 `BACKUP_DIR` 调整。
- 页面展示受管理备份的最近生成/校验时间、文件是否仍存在及大小是否一致；超过 48 小时提示更新。可手动生成校验备份，不自动新增备份 cron，不提供网页恢复或删除操作。
- 页面显示数据库体积、磁盘余量、ETF 快照数量/日期，缓存文件数不能证明所有涨幅窗口完整。
- `.cache/`、`backups/` 均不纳入 Git，不把真实凭据写入代码或页面。
