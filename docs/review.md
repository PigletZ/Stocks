# 涨停复盘（连板梯队 + 情绪周期）

## 当前版本：复盘工作台

- 区间价格比较增加统一复权口径：`(结束收盘×结束因子)/(开始收盘×开始因子)-1`。只取对应交易日及所选截止日之内的 Tushare 因子；缺失报价或因子留空，不以 1 或最近日期代替。原始收盘与旧版 `price_change` 字段保留，新增 `adjusted_price_change` 独立展示；这不是账户实际收益。
- 每个价格规则版本保存 `price_basis=raw|adjusted`。迁移将旧规则保留为 raw，旧客户端未传此项仍按 raw；新网页价格模板明确提交 adjusted。追加规则时可选择口径，原始判断和旧版本继续保留。期间规则需逐日因子，期限规则只依赖起止点；有效反例可立即提示，其他缺失仍展示。
- 关注详情提供“补齐复权数据”，按单只股票及限定区间从官方源补齐因子；普通列表、提醒和 AI 上下文仅读本地因子。AI 证据同时保留原始报价、对应因子及规则口径，审阅提示版本升级后旧意见标为需要复核，原快照不改写。
- 每条 AI 意见可标注“有帮助、理解有误、证据不足”，后两类须填写依据。反馈与 AI 原文、人工验证分开保存；修改追加版本，相同重复提交复用原记录，按所属日期回看且展示实际录入时间。可分页查看单条意见的反馈历史。汇总只计各意见最新标注，不重复累计修改次数，也不解释为模型准确率。保存反馈不重新调用模型或改变原审阅的事实指纹。
- 反馈接口：`POST/GET /api/review/observations/{id}/audits/{audit_id}/feedback`；因子补齐：`POST /api/review/observations/{id}/factors?date=`。均沿用登录鉴权，核对审阅与关注关系、意见分组/序号及历史日期范围。
- 本轮需先备份，再执行 `PYTHONPATH=. venv/bin/python scripts/migrate_add_price_basis_feedback.py`；重复执行安全。首次回填使用 `venv/bin/python scripts/sync_price_factors.py --days 35`，之后原有 16:00/18:30/20:30 日任务补齐最近三个真实交易日的股票因子和 ETF 因子缓存。未发布记为待补齐，失败保留旧值，缓存命中不冒充新写入。

- 关注入口支持股票名称/代码搜索，以及“自定义文字条件、期限日收盘表现、期间收盘保持条件”模板。3/5/10 个交易日期限取自官方日历（排除关注日），不按工作日猜测；打开录入时按需读取，失败可手动选日期。选择价格模板不会自动激活规则，须明确勾选后与关注在同一事务中保存，规则校验失败时整条新关注回滚。
- 关注清单按待验证、到期、已完成、全部分类，可搜索股票/理由并分页；默认只显示判断摘要、核对状态、下一步和上次 AI 日期，按需展开详情。提醒点击可直接打开分页范围之外的旧关注。工作台主请求使用 `include_observations=false`，不再为新页面预加载兼容接口的最近 500 条记录。
- 提醒核对全部未完成关注，以及有价格规则的人工通过结论，不以最近 500 条截断。清单和提醒分别分页；总数按完整核对范围计算。最新规则/验证/审阅使用数据库窗口查询，报价分批读取；已读与暂缓记录仍按所选日期对齐。
- 跨日展示截至所选日期最近一次 AI 意见，明确历史依据日期和真实生成时间，并显示新增/更新报价、规则、验证及覆盖变化。可分页查看更早的审阅及其原始证据快照；读取历史不调用模型，后续数据不改写旧证据，未来所属日期的审阅不可通过单独记录接口绕过限制。
- 新增只读接口：`GET /api/review/observations?date=&status=&search=&page=&page_size=`、`GET /api/review/observations/{id}?date=`、`GET /api/review/observations/{id}/audits?date=&page=`、`GET /api/review/observations/{id}/audits/{audit_id}?date=`、`GET /api/review/deadlines?date=`。本轮复用既有表，无数据库结构变更。

- 工作台顶部“待验证与审阅提醒”：集中显示到期关注、已确认价格条件的反例、人工“符合预期”与反例的冲突、缺少条件或数据的事项。提醒按关注/规则版本/事件去重，支持已读、次日再提醒与恢复；在所选复盘日期生效，不隐藏此前历史页面。新规则或新反例不会被旧已读状态吞掉。
- 每条关注可人工确认两类价格条件：期限日收盘涨跌幅、期间每个交易日收盘涨跌幅（相对关注日，支持上下界）。期间不含关注日，期限为休市日时取此前最后一个真实交易日。条件修改追加版本，保存所属复盘日期、确认说明及实际保存时间；原始理由和文字条件不改写，事后补充不得被解释为事前标准。
- 价格核对只用本地官方日历缓存和截止所选日期/原始期限的报价，不访问行情源、不用工作日推测。未到期限不提前判定通过；期间规则发现有效反例即可提示，缺少报价或日历则保留未知。价格未复权，不是含分红收益；价格条件通过不等于整体判断正确。自动核对目前限一年内、有后续交易日的关注期限。
- 单条“AI 审阅”由用户手动触发，页面加载不会调用模型。仅发送这一条原始关注、人工规则/验证、数据覆盖、基准及最近报价与市场背景；返回“支持证据、相反证据、尚不能确认、下一次验证”。每条意见须引用发送的事实 ID，非法引用、截断结果、超时或接口失败不写入假成功结果。
- AI 意见与人工验证分开保存。保存引用资料快照、模型、截至日期、真实生成时间；相同证据复用结果，重新生成或输入变化后的再次调用间隔至少两分钟，同一服务进程仅接受一个进行中的审阅。规则、验证或行情变化后旧意见标记过期；请求过程中资料变化也会提示过期。模型不联网检索、不开工具、不自动执行交易或修改记录，未知消息不得推断成事实。

## 数据落库

涨跌停/龙虎榜明细此前每次实时拉取、不落库。本模块新增两张缓存表：

| 表 | 来源接口 | 说明 |
|---|---|---|
| `limit_up_daily` | `limit_list_d` | 涨停(U)/跌停(D)/炸板(Z) 明细：连板数、涨停统计、封单额、首封/末封时间、开板次数等 |
| `dragon_tiger_daily` | `top_list` | 龙虎榜：买卖额、净买额、上榜原因（同票多条按 code 聚合），为回测本地化做准备 |

- 唯一键均为 `(stock_code, trade_date)`，当天整体覆盖式写入（delete + insert）
- 数据未就绪（空表/异常）时不触碰已有数据
- 每日 cron：`scripts/import_daily.py`（16:00）已增加两张表的同步步骤
- 历史回填：`scripts/import_limit_history.py`，已回填 2024-01-02 至今（与 marketdailystat 对齐，618 个交易日），已落库日期自动跳过可续传

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/review/limit-ladder?date=` | 连板梯队：涨停股按连板数分组（从高到低），含首封时间/开板次数 |
| `GET /api/review/limit-performance?date=` | 昨日涨停今日表现：晋级率、平均涨幅、明细（晋级/炸板/红盘/绿盘/跌停） |
| `GET /api/review/emotion?start&end` | 情绪周期时间序列：涨停/跌停/炸板数、炸板率、晋级率、最高板、成交额 |
| `POST /api/review/sync?date=` | 手动触发指定日期落库 |

## 口径说明

- **晋级**：昨日涨停（U）今日仍涨停
- **炸板率** = 炸板数 /（涨停数 + 炸板数），基于 marketdailystat
- **晋级率** = 今日涨停中昨日也涨停的家数 / 昨日涨停家数，基于 limit_up_daily
- **最高板**：当日涨停股最大连板数
- 昨日涨停的今日涨幅：优先取今日涨跌停表，其次 `stockdailyquote`，早于其覆盖范围（2026-04 之前）实时拉 `daily` 补齐（单日一次请求）

## 前端

- 连板梯队页：统计卡（昨日涨停数/晋级率/平均涨幅）+ 梯队图（按板数分列，点击个股打开 K 线明细弹窗）+ 昨日涨停今日表现明细表
- 情绪周期页：最新一日摘要卡 + 两张 ECharts（涨跌停与最高板 / 炸板率与晋级率），快捷区间 近一月~全部

# 复盘日志（笔记 + 交易台账）

## 功能入口

- 复盘日志：`/review/journal`

## 数据表

| 表 | 说明 |
|---|---|
| `review_note` | 每日复盘笔记（`note_date` 唯一，Markdown 文本 + 关联股票 codes JSON） |
| `trade_journal` | 真实交易台账（code/direction/price/quantity/fee/traded_at/note） |

## 接口（`/api/journal`）

| 接口 | 说明 |
|---|---|
| `GET/PUT/DELETE /note?date=` | 笔记查询/保存/删除 |
| `GET /note-dates?year&month` | 当月有笔记/有交易的日期（日历标记） |
| `GET/POST /trades`，`PUT/DELETE /trades/{id}` | 交易台账 CRUD；卖出数量超过该时点持仓会被拒绝 |
| `GET /positions` | 当前持仓：FIFO 成本（含买入费用摊薄）+ 最新收盘浮动盈亏 |
| `GET /stats` | 已实现盈亏、胜率（按卖出笔数）、买卖次数、累计费用 |

## 口径说明

- 持仓成本用 FIFO：卖出时从最早买入批次扣减，每股成本含买入费用摊薄
- 卖出盈亏 =（卖价 - FIFO 成本）× 数量 - 卖出费用；历史买入未录入导致的超卖部分按 0 成本计并记日志
- 页面三个 Tab：复盘笔记（日历 + 编辑器 + 当日交易）、交易台账（录入 + 明细表）、当前持仓
